## 1. 项目概述

### 1.1 项目目标

实现一套自托管的幻兽帕鲁（Palworld）专用服务器管理工具，在参考项目已有功能的基础上，**重点强化反作弊能力**：

- 通过可视化 Web 界面和 REST 接口管理服务器、玩家、公会、帕鲁、物品、白名单、备份；
- 通过官方 REST API + RCON 实时获取在线数据并执行管理操作；
- 通过周期性解析 `Level.sav` 存档文件获取完整玩家/帕鲁/背包数据；
- **反作弊**（设计参考 PalDefender）：对存档数据进行异常检测（属性篡改、非法物品、复制帕鲁、加速升级、非法 IV/词条等），对在线行为进行异常检测（瞬移、同 IP 多开、重复登录等），支持四级处置阶梯（**警告 → 踢人 → 封禁 → IP 封禁**），并提供帕鲁净化（block/clamp/remove）、证据留存、审计与全服通告；
- 可选集成 **PalDefender**（服务端注入式反作弊）：在 Wine/Proton 下对接其 REST API（`:17993`）与 `Banlist.json`/`ImportRules`，获得进程内实时检测（伤害校验、非法 stat 拦截等）；原生 Linux 下以存档扫描为主。

### 1.2 功能清单

| 模块 | 功能 |
| --- | --- |
| 服务器信息 | 版本、名称、描述、FPS、在线人数、帧时间、 uptime |
| 在线玩家 | 列表、昵称、SteamID、PlayerUID、IP、Ping、坐标、等级 |
| 玩家存档 | 等级、经验、HP/护盾、状态点、饱腹度、帕鲁列表、背包物品 |
| 帕鲁 | 等级、经验、HP、词条、技能、性别、幸运/Boss/塔主标记、rank、IV（个体值）|
| 公会 | 名称、据点等级、成员、据点 ID |
| 管理操作 | 广播、踢人、封禁/解封、平滑关服、自定义 RCON 命令 |
| 白名单 | 增删改查、非白名单自动踢出 |
| 备份 | 定时备份存档、列表、下载、删除、一键回档 |
| **反作弊** | 规则引擎、存档扫描、在线行为扫描、证据快照、告警、分级处置、审计日志 |
| 多服务器 | 支持配置多个游戏服务器（后续版本） |

### 1.3 与参考项目的差异

- 新增独立的 `anticheat` 模块，包含规则引擎、检测器、处置器、证据库；
- 数据模型扩展：新增帕鲁个体值（IV）、实例 ID、物品堆叠上限、玩家历史快照等反作弊必需字段；
- 新增 Webhook / 告警通道；
- 新增审计日志（audit log）记录所有管理与处置动作；
- 前端新增「反作弊」页面：告警列表、规则配置、证据查看、处罚记录；
- 预留 `agent`/`mod` 接口，用于接收注入式反作弊的实时事件。

### 3.2 数据流

1. **在线数据流**：定时任务 → `tool.ShowPlayers()` 调官方 REST `/v1/api/players` → 写入 bbolt `players` bucket → 同时推送给反作弊在线行为检测器。
2. **存档数据流**：定时任务 → `tool.Decode()` 调 sav_cli 解析 `Level.sav` → sav_cli 通过本地回环 HTTP `PUT /api/player`、`PUT /api/guild` 回传 → Service 层持久化 → 触发反作弊存档扫描器。
3. **反作弊处置流**：检测器产出 `Finding` → 规则引擎匹配严重等级与处置阶梯（warn/kick/ban/ipban）→ 处置器调用官方 REST/RCON 或 PalDefender REST 执行 → 证据写入 bbolt 并落盘为 JSON 文件、写审计、告警推送 Webhook、全服通告。
4. **PalDefender 集成流（可选）**：管理端调用 PalDefender REST（`:17993`）读取实时玩家/帕鲁/物品/封禁数据，并接收/拉取其检测事件 → 进入统一处置器与面板；双向同步 `Banlist.json` 与帕鲁净化规则。

## 6. 数据模型与存储设计

### 6.1 bbolt Buckets（当前状态 / 配置）

| Bucket | Key | Value | 说明 |
| --- | --- | --- | --- |
| `players` | PlayerUID | `Player` JSON | 玩家完整数据（含在线态与存档态合并） |
| `guilds` | AdminPlayerUID | `Guild` JSON | 公会数据 |
| `whitelist` | Name\|SteamID\|PlayerUID | `PlayerW` JSON | 白名单 |
| `rcons` | UUID | `RconCommandList` JSON | 自定义 RCON 命令 |
| `backups` | BackupId | `Backup` JSON | 备份元数据 |
| `settings` | key | string | 运行时设置（反作弊开关、阈值等） |

### 6.2 bbolt Buckets（历史快照 / 反作弊 / 审计）

所有时序数据同样存进 `pst.db`。bbolt 是有序 KV，用 **big-endian uint64 序列号**（`bucket.NextSequence()`）作为 key 后缀，即可保证按时间正序遍历；再用「字段 + 序列号」组成的复合 key 建立二级索引。一次扫描产生的多条记录在**同一个读写事务**里批量写入，避免单写者竞争。

| Bucket | Key | Value | 说明 |
| --- | --- | --- | --- |
| `ac_alerts` | `seq(8B BE)` | `Alert` JSON | 告警主表，按 seq 升序即按时间升序 |
| `ac_alerts_player` | `player_uid \| seq(8B BE)` | `seq(8B BE)` | 按玩家索引，前缀扫描即可查某玩家的全部告警 |
| `ac_alerts_status` | `status \| seq(8B BE)` | `seq(8B BE)` | 按状态（open/confirmed/...）索引 |
| `ac_audit` | `seq(8B BE)` | `Audit` JSON | 审计日志 |
| `ac_rules` | `rule_id` | `Rule` JSON | 规则配置（覆盖代码默认值） |
| `player_snapshots` | `player_uid \| seq(8B BE)` | `Snapshot` JSON | 玩家历史快照，按玩家前缀扫描；**每玩家保留最近 N 条**（默认 200，可配），超出在写入时删除最旧 |
| `pal_snapshots` | `owner_uid \| instance_id` | `PalSnapshot` JSON | 每个玩家当前拥有的每只帕鲁的最新状态（复制检测在单次扫描的内存中完成：同一 `instance_id` 出现在多个 owner 下即命中 S007） |
| `ac_counters` | `metric_name` | uint64 | 运行期计数器（累计封禁数、告警数等，供统计页快速读取） |

序列号写入示例：

```go
seq, _ := b.NextSequence()
key := make([]byte, 8)
binary.BigEndian.PutUint64(key, seq)
b.Put(key, alertJSON)
// 二级索引
b2, _ := tx.CreateBucketIfNotExists([]byte("ac_alerts_player"))
idx := append([]byte(playerUID), '|')
b2.Put(append(idx, key...), key)
```

查询模式：
- 「最近 100 条告警」：`ac_alerts` 反向游标取 100 条；
- 「某玩家的告警」：`ac_alerts_player` 前缀扫描拿 seq，再 `ac_alerts.Get(seq)`；
- 「未处理告警」：`ac_alerts_status` 前缀 `open|` 扫描；
- 「玩家 X 的等级变化趋势」：`player_snapshots` 前缀 `X|` 扫描，逆序取 N 条。

数据保留策略：
- 玩家快照每玩家保留最近 `snapshot.keep_per_player`（默认 200）条；
- 审计日志与告警默认保留 `retention.days`（默认 90 天），由每日清理任务删除早于阈值的 key；
- 证据 JSON 文件存放在磁盘 `evidence/` 目录，由告警清理任务同步回收。

## 7. 存档解析模块

### 7.1 流程（沿用参考项目设计）

1. 定时任务 `SavSync()` 调用 `tool.Decode(save.path)`；
2. `getFromSource()` 根据 `save.path` 前缀支持四种来源：
   - 本地路径：`/path/to/Pal/Saved`
   - HTTP：`http://agent:8081/sync`（pst-agent）
   - Docker：`docker://container:/palworld/Pal/Saved`
   - k8s：`k8s://ns/pod/container:/palworld/Pal/Saved`
3. 将 `Level.sav` 拷贝到临时目录，调用 `sav_cli`：
   ```
   sav_cli -f /tmp/xxx/Level.sav --request http://127.0.0.1:8080/api/ --token <JWT>
   ```
4. sav_cli 解析 `.sav`（Unreal Engine GVAS 格式），输出结构化 JSON，通过 HTTP `PUT /api/player` 与 `PUT /api/guild` 回传；
5. Service 层合并在线数据后写入 bbolt（`players`/`guilds`），并把本次玩家/帕鲁数据写入 `player_snapshots`/`pal_snapshots` 供反作弊趋势分析；
6. 触发反作弊存档扫描器；
7. 清理临时目录。

### 7.2 解析器增强项

参考项目 `module/structurer.py` 当前仅解析等级、HP、技能、性别、幸运/Boss 标记。反作弊需要补充：

- 帕鲁 **Instance ID**（存档中的 `InstanceId`）；
- **天赋 / 个体值**（`Talent_HP/Melee/Shot/Defense`，取值 0~100）；
- **被动技能词条**全量列表（用于检测非法词条组合，如全属性 + 词条堆叠）；
- **rank / 阶级** 与 **强化次数**；
- 物品的 **耐久、自定义数据、附加属性**；
- 玩家 **IP 与登录时间**（在线数据已有，存档中亦可补充）；
- 帕鲁 **主人 / 所属公会** 关联；
- **据点建筑数据**（可选，用于检测异常建筑）。

### 7.3 性能

- 解析过程在 1~3 GB 内存内、<20s 完成；
- `sav_cli` 解析与 Go 主进程隔离，避免解析崩溃影响服务；
- 临时目录由 5 分钟一次的清理任务回收（参考项目 `system.LimitCacheDir`）。

## 9. 反作弊引擎（核心）

> **设计参考：PalDefender（Ultimeit/PalDefender）。** PalDefender 是一款成熟的幻兽帕鲁**服务端注入式**反作弊：通过 `d3d9.dll` 代理加载 `PalDefender.dll` 进游戏服务端进程，在**玩家操作执行前**做服务端校验，并按「警告→踢出→封禁→IP 封禁」四级处置。它是闭源 Windows DLL（Linux 需 Wine/Proton），源码不公开。
>
> 本项目目标平台为 **Ubuntu 22.04**，因此我们不依赖 PalDefender 二进制，而是**复刻其检测理念、处置阶梯、配置模型与命令集**，用 Go 在进程外实现，并预留与 PalDefender 原生 REST API 对接的能力。

### 9.1 双模式架构

| 模式 | 适用场景 | 检测方式 | 实时性 |
| --- | --- | --- | --- |
| **外置模式（默认）** | 任意 Linux 私服，包括原生 Linux 服务端 | 存档扫描 + 官方 REST/RCON 轮询 | 秒级~分钟级 |
| **PalDefender 集成模式（可选）** | 服务器在 Wine/Proton 下安装了 PalDefender | 调用 PalDefender REST API（`:17993`）接收实时事件、执行封禁/净化 | 实时 |

外置模式保证「任何服务器都能用」；集成模式在已有 PalDefender 时获得其进程内实时 hook 能力（伤害校验、非法帕鲁 stat 拦截、IP 封禁等），管理端作为统一面板与持久化层。

三层数据流：**数据采集 → 规则检测 → 处置响应**。

### 9.2 设计原则（对标 PalDefender）

- **服务端校验优先**：所有判定以服务端数据（存档/REST/PalDefender 事件）为准，不信任客户端；
- **分级处置**：`warn`（私聊警告）→ `kick` → `ban`（UserId）→ `ipban`，四级可独立开关（对应 PalDefender 的 `shouldWarnCheaters`/`shouldKickCheaters`/`shouldBanCheaters`/`shouldIPBanCheaters`）；
- **可配置 + 热加载**：每条规则可开关、调阈值、选动作，配置改动经 `/reloadcfg` 或接口热生效；
- **白名单豁免**：管理员/白名单玩家不被自动处置，但仍记录告警；管理员命令受 IP 白名单保护（对应 `useAdminWhitelist`/`adminIPs`）；
- **证据留存 + 审计**：每次触发保存证据快照，所有处置写审计日志，支持申诉解封；
- **处罚通告**：可向全服通告封禁/踢出（对应 `announcePunishments`）。

### 9.3 检测规则

#### 9.3.1 存档类规则（Save Rules，外置模式主力）

每次存档同步后对全体玩家/帕鲁/物品扫描。规则 ID 与检测项对标 PalDefender 的 `Config.json` 与 ImportRules。

| 规则 ID | 名称 | 检测逻辑 | 对应 PalDefender 配置 | 默认动作 |
| --- | --- | --- | --- | --- |
| `S001` | 帕鲁非法属性 | HP/攻击/防御/工作速度/等级/rank 超过该物种合法上限或 `palStatsMaxRank` | `doActionUponIllegalPalStats`, `palStatsMaxRank` | ban |
| `S002` | 非法 IV / 词条 | 个体值 IVs 越界（>100）、PalSouls 越界、被动词条不在合法表或数量 >4 | ImportRules `IVs`/`PalSouls`/`DisallowedPassives` | ban |
| `S003` | 非法持有塔主/Boss 帕鲁 | 拥有 `is_tower`/`is_boss` 标记或 `BOSS_*` ID 的帕鲁 | `blockTowerBossCapture` | ban |
| `S004` | 帕鲁净化（Import） | 对越界帕鲁按策略处理：`BlockImport`（标记/删除）/`ClampToMaxValues`（截断到上限）/`RemoveFromPal`（移除非法词条） | ImportRules `MaxValueLimitAction`/`DisallowedPassivesAction` | 按策略 |
| `S005` | 非法物品 | 持有调试物品/Mod 物品/任务物品；堆叠数超过最大堆叠 | `disableIllegalItemProtection`(反向) | kick |
| `S006` | 复制帕鲁 | 同一 `instance_id` 出现在多个玩家身上；或 IV/技能/等级高度一致的帕鲁跨玩家重复 | —（本项目增强） | ban |
| `S007` | 玩家属性越界 | 等级超上限、HP 超理论最大值、状态点异常、经验为负 | — | ban |
| `S008` | 进度异常增长 | 与上次快照对比，等级/经验/物品在单位时间内增长超阈值 | — | kick |
| `S009` | 非法科技 | 习得了 `bannedTechnologies` 中的科技 | `bannedTechnologies` | kick |
| `S010` | 非法据点 | 据点数超上限、等级越界、重叠/越界建筑 | `BaseCampMaxNumInGuild` 等 | notify |
| `S011` | 违禁昵称 | 昵称匹配 `bannedNames`（如盗版/破解版标记名） | `bannedNames` | kick |
| `S012` | 金钱/资源异常 | 金币或关键资源超上限或短时暴增 | — | notify |

> S004 的「帕鲁净化」是 PalDefender 的特色：不是简单封禁，而是把越界数值**截断**或把违禁词条**移除**后保留帕鲁，适合不想误封正常玩家的服务器。

#### 9.3.2 在线行为规则（Live Rules）

通过官方 REST API（`:8212`）轮询在线玩家（默认 60s），内存中维护历史。

| 规则 ID | 名称 | 检测逻辑 | 对应 PalDefender | 默认动作 |
| --- | --- | --- | --- | --- |
| `L001` | 速度异常 / 瞬移 | 两次轮询间位移/时间 > 阈值（传送点坐标白名单） | —（外置增强） | kick |
| `L002` | 同 IP 多开 | 同 IP 同时在线账号数 > 阈值 | —（日志 `logPlayerIP`） | notify |
| `L003` | 重复登录 | 同一 UserId 重复在线 | `steamidProtection` | kick |
| `L004` | 非白名单在线 | 玩家不在 `WhiteList.json` | `useWhitelist`/`whitelistMessage` | kick |
| `L005` | 聊天违禁词 | （集成模式）聊天命中 `bannedChatWords` | `bannedChatWords` | warn/kick |
| `L006` | 伤害异常 | （集成模式）PvP/PvE 伤害超 `pvpMaxToPalDamage`/`pveMaxToPalBanThreshold` | 伤害阈值配置 | ban |

#### 9.3.3 集成模式事件（PalDefender Events）

当配置 `paldefender.address` 且可达时，管理端订阅/接收 PalDefender 的检测事件（其 REST API 本身不推送，管理端可定期拉取 banlist 与玩家数据；实时事件由 PalDefender 的日志或可选 Webhook 解析）。涵盖：非法帕鲁 stat、非法物品、塔主捕获、伤害作弊、聊天违禁等。这些事件直接进入处置器，告警来源标记为 `paldefender`。

### 9.4 处置阶梯（Punishment Ladder）

完全对标 PalDefender 的四级开关，每级可独立启用：

```go
type Action string
const (
    ActionWarn  Action = "warn"  // 私聊警告玩家（shouldWarnCheaters + shouldWarnCheatersReason）
    ActionKick  Action = "kick"  // 踢出（shouldKickCheaters）
    ActionBan   Action = "ban"   // UserId 封禁（shouldBanCheaters）
    ActionIPBan Action = "ipban" // IP 封禁（shouldIPBanCheaters）
)
```

处置流程：
1. 命中规则 → 按规则 `action` 执行（可配多级，如 `["warn","kick"]`）；
2. `warn`：通过 `/send` 或 PalDefender `SendPlayerMessage` 向玩家私聊发送原因；
3. `kick`：官方 REST `/v1/api/kick` 或 PalDefender `/kick`；
4. `ban`：写入 `Banlist.json`（UserId），调用封禁接口；封禁前可自动备份存档（`backup.on_ban`）；
5. `ipban`：先 `/getip` 取 IP，写 `Banlist.json` 的 IP 段，调用 `/banip`；
6. `announcePunishments` 开启时全服 `/pgbroadcast` 通告；
7. 全程写审计日志与告警记录。

```go
func ExecuteAction(f Finding) error {
    for _, act := range f.Rule.Actions {
        switch act {
        case ActionWarn:
            tool.SendPlayerMessage(f.UserId, "log", f.Rule.Reason)
        case ActionKick:
            tool.KickPlayer(f.UserId, f.Rule.Reason)
        case ActionBan:
            if cfg.Backup.OnBan { tool.Backup() }
            tool.BanPlayer(f.UserId, f.Rule.Reason)
            banlist.AddUser(f.UserId, f.Rule.Reason)
        case ActionIPBan:
            ip, _ := tool.GetPlayerIP(f.UserId)
            tool.BanIP(ip)
            banlist.AddIP(ip, f.Rule.Reason)
        }
    }
    if cfg.Anticheat.AnnouncePunishments {
        tool.Broadcast(fmt.Sprintf("玩家 %s 因 %s 被处置", f.Nickname, f.Rule.Reason))
    }
    audit.Log("anticheat", string(f.Rule.Actions[0]), f.UserId, f.Title, "success")
    return nil
}
```

### 9.5 封禁与白名单（Banlist / Whitelist）

- **Banlist**：兼容 PalDefender 的 `Banlist.json`，记录 UserId 封禁与 IP 封禁两类条目，每条含原因、时间、发布者（issuer）；管理端维护在 bbolt，集成模式下与 PalDefender 的文件双向同步；
- **WhiteList**：兼容 PalDefender 的 `WhiteList.json`，支持 UserId 和 IP（含掩码/网段）；`useWhitelist` 启用后仅名单内玩家可进入，其余收到 `whitelistMessage` 后被踢；
- **命令**：`/ban`、`/unban`、`/ipban`、`/banip`、`/unbanip`、`/getip`（对标 PalDefender）；
- **RESTConfig**（集成模式）：PalDefender 的 `RESTAPI/RESTConfig.json` 控制启用、绑定地址、端口（默认 17993）、CORS；`Tokens/*.json` 为每个使用者/服务签发独立 Bearer Token 与权限范围（如 `REST.Punishments.Ban`），管理端只授予所需最小权限；
- **管理员保护**：`useAdminWhitelist` + `adminIPs`，仅白名单 IP 可使用管理员命令（对应 PalDefender 防管理员密码泄露机制）；`steamidProtection` 防止同一 UserId 重复登录。

### 9.6 帕鲁净化规则（ImportRules 模型）

参考 PalDefender 的 `Pals/ImportRules/` 设计一套「帕鲁合法性策略」，既可用于存档扫描，也可在集成模式下下发给 PalDefender：

- `Default.json`（全局）+ `<PalID>.json`（按物种覆盖）；
- 字段：`MaxLevel`、`MaxRank`、`PalSouls{Health,Attack,Defense,CraftSpeed}`、`IVs{Health,AttackMelee,AttackShot,Defense}`、`DisallowedPassives`、`BannedPalIDs`/`AllowedPalIDs`、`AllowGenderNone`；
- 三种处置策略：
  - `BlockImport`：发现越界即标记违规（外置模式下触发 S001/S002，可封禁）；
  - `ClampToMaxValues`：把等级/rank/灵魂/IV 截断到上限（自动净化，不封禁）；
  - `RemoveFromPal`：移除违禁被动词条后保留。

策略文件位于 `data/palrules/`，前端提供可视化编辑器。

### 9.7 规则引擎

```go
type Severity string // info / warn / critical

type Rule struct {
    ID          string                 `json:"id"`
    Name        string                 `json:"name"`
    Category    string                 `json:"category"` // save / live / integrated
    Enabled     bool                   `json:"enabled"`
    Severity    Severity               `json:"severity"`
    Actions     []Action               `json:"actions"`  // warn/kick/ban/ipban 可组合
    Reason      string                 `json:"reason"`   // 告知玩家的原因
    Params      map[string]any         `json:"params"`
    Description string                 `json:"description"`
}

type Finding struct {
    Rule      Rule
    UserId    string // steam_xxx / gdk_xxx（PalDefender 统一用 UserId）
    PlayerUID string
    Nickname  string
    PalInstID string
    Title     string
    Detail    map[string]any
    Evidence  []byte
    Source    string // internal / paldefender
}
```

引擎流程：扫描器产出 Finding → 规则匹配（enabled/白名单豁免）→ 冷却去重（同 rule+player 在 `cooldown` 秒内不重复）→ 写 `ac_alerts` + 证据文件 → 执行处置阶梯 → 告警通知。

### 9.8 合法数据表

存放于 `data/gamedata/`，随游戏版本更新：

- `pals.json`：物种基础属性上限、等级上限、是否可捕获、可拥有词条；
- `items.json`：物品最大堆叠、合法来源、是否调试/违禁物品；
- `passives.json`：合法被动词条 ID；
- `technologies.json`：合法科技 ID；
- `limits.json`：等级上限、据点上限、金币上限等。

ID 查询参考 PalDefender 文档推荐的 paldeck.cc（pals/items/technology/passives/skills）。

### 9.9 证据、日志与审计

- 证据：critical 告警导出玩家存档片段为 `evidence/<alert_id>.json`；可选快照整个 `Level.sav`（受配额限制）；
- 日志分类对标 PalDefender：聊天、RCON、网络、登录登出、死亡、建筑、召唤/捕获帕鲁、制作、科技解锁、空岛宝箱等（`logChat`/`logRCON`/`logPlayerLogins`/...），写入 bbolt 与滚动日志文件；
- 审计：所有管理/处置动作（谁、对谁、做了什么、结果）入 `ac_audit`；
- 告警页支持「确认作弊 / 误报 / 忽略 / 一键解封」。

### 9.10 PalDefender 集成模式

当服务器（通常 Wine/Proton）装有 PalDefender 并启用其 REST API（默认 `http://127.0.0.1:17993`，Bearer Token，细粒度权限如 `REST.Players.Read`、`REST.Punishments.Ban`）：

- 管理端作为 PalDefender 的客户端，复用其更丰富的实时数据与能力：
  - 读取：`/players`、`/player/<id>`、`/pals/<id>`、`/items/<id>`、`/techs/<id>`、`/guilds`、`/banlist`、`/version`；
  - 处置：`/kick`、`/ban`、`/unban`、`/banip`、`/unbanip`；
  - 消息：`/Broadcast`、`/Alert`、`/SendPlayerMessage`；
  - 奖励/净化：`/give/items`、`/give/pals`、`/give/paltemplate`、`/deletebase`、`/learntech`、`/forgettech`、`/ReloadConfig`；
- Token 按最小权限原则发放（例如面板只读用 `REST.*.Read`，处置用单独 token）；
- 同步 `Banlist.json` 与 ImportRules；
- **安全**：PalDefender 的 17993 端口绝不暴露公网，管理端通过内网或反向代理访问。

> PalDefender 官方仅支持 Windows，Linux 需自行用 Wine/Proton 承载。若使用原生 Linux 服务端，则仅用外置模式，功能集是 PalDefender 的超集面板 + 子集实时检测（存档扫描为主）。

## 14. 备份与恢复

- 备份格式：zip 压缩整个 Saved 目录（Level.sav + Players/ + 配置等），文件名 `2006-01-02-15-04-05.zip`；
- 元数据写入 bbolt `backups` bucket；
- 保留策略：按 `keep_count` 与 `keep_days` 双重清理；
- **回档流程**（新增）：
  1. 广播通知并 `Shutdown`；
  2. 等待进程退出（systemd/Docker 控制）；
  3. 备份当前存档到 `backups/rollback-<time>.zip`（安全网）；
  4. 解压目标备份覆盖 Saved；
  5. 启动服务端；
  6. 校验 `metrics` 恢复在线。
- 回档需要管理端对游戏服务端进程有控制权（systemd 或 docker socket），在文档中明确部署要求。

## 15. 安全设计

1. **密码**：Web 密码首次启动若为空则强制设置；JWT 密钥在首次启动随机生成并写入 `settings` bucket。
2. **JWT**：HS256，有效期 24h，支持登出失效（内存黑名单或短过期 + refresh）。
3. **PalDefender Token**：集成模式使用 PalDefender 签发的 Bearer Token，按最小权限授予（如只读面板仅 `REST.*.Read`，处置用独立 token）；其 17993 端口严禁暴露公网，管理端经内网/反代访问。
4. **TLS**：生产环境开启 `web.tls` 或放在 Nginx/Caddy 反向代理后启用 HTTPS。
5. **REST/RCON 密码**：仅保存在本机配置文件（0600 权限），严禁提交到仓库；支持环境变量注入。
6. **反作弊误防护**：封禁前自动备份；支持快速解封；白名单玩家（管理员）默认豁免所有自动封禁，但仍记录告警。
7. **CORS**：默认仅允许同源；如需跨域显式配置白名单。
8. **限流**：登录接口与 RCON 发送接口加限流，防止暴力破解与误操作。
9. **权限隔离**：管理端仅监听 127.0.0.1 或内网，公网暴露必须经反向代理 + HTTPS + 强密码。

## 17. 部署方案（Ubuntu 22.04）

提供两种方式：**Docker Compose（推荐）** 与 **systemd 裸机部署**。

### 17.1 Docker Compose 部署（推荐）

假设游戏服务端以容器名 `palworld` 运行，存档目录在宿主机 `/home/steam/Pal/Saved`。

`docker-compose.yml`：

```yaml
services:
  pst:
    build: .
    image: palworld-admin:latest
    container_name: palworld-admin
    restart: unless-stopped
    ports:
      - "8080:8080"
    volumes:
      - ./config.yaml:/app/config.yaml:ro
      - ./backups:/app/backups
      - ./evidence:/app/evidence
      - ./logs:/app/logs
      - pst-db:/app/data
      - /home/steam/Pal/Saved:/game:ro
      - /var/run/docker.sock:/var/run/docker.sock  # 用于回档控制游戏容器
    environment:
      WEB__PASSWORD: "CHANGE_ME"
      REST__ADDRESS: "http://palworld:8212"
      REST__PASSWORD: "your_admin_password"
      RCON__ADDRESS: "palworld:25575"
      RCON__PASSWORD: "your_admin_password"
      SAVE__PATH: "/game"
      ANTICHEAT__ENABLED: "true"
    # 若游戏端在同一 compose 网络，可使用服务名互联

volumes:
  pst-db:
```

启动：

```bash
docker compose up -d
docker compose logs -f
```

访问 `http://<服务器IP>:8080`，使用 `WEB__PASSWORD` 登录。

### 17.2 systemd 裸机部署

```bash
# 1. 创建运行用户
sudo useradd -r -m -d /opt/pst pst

# 2. 解压发行包
sudo mkdir -p /opt/pst && sudo tar -xzf pst_linux_x86_64.tar.gz -C /opt/pst
sudo chown -R pst:pst /opt/pst
sudo chmod +x /opt/pst/pst /opt/pst/sav_cli

# 3. 修改 /opt/pst/config.yaml
sudo -u pst vim /opt/pst/config.yaml

# 4. 安装 systemd 服务
sudo cp scripts/palworld-admin.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now palworld-admin
sudo systemctl status palworld-admin
```

## 18. 开发与构建

### 18.1 Makefile

```makefile
BACKEND := palworld-admin
VERSION := $(shell git describe --tags --always 2>/dev/null || echo dev)

.PHONY: all web backend run clean

web:
	cd web && npm install && npm run build

backend:
	CGO_ENABLED=0 go build -trimpath -ldflags "-s -w -X main.version=$(VERSION)" -o $(BACKEND) .

all: web backend

run:
	go run . --config config.yaml

clean:
	rm -rf $(BACKEND) web/dist

sav-cli:
	cd module && pip install -r requirements.txt
```

> 纯 bbolt 方案无 CGO 依赖，`CGO_ENABLED=0` 即可编译出**纯静态二进制**，不依赖 glibc，可在任意 Linux x86_64（含 Alpine、Ubuntu 22.04）直接运行，交叉编译也非常简单。

### 18.2 前端构建嵌入

- `web/` 执行 `npm run build` 产出 `web/dist/`；
- 后端使用 `//go:embed all:web/dist` 嵌入静态资源；
- 参考项目将 `index.html` 与 `assets/` 拷贝到根目录再 embed，本项目改为直接 embed `web/dist`。

### 18.3 交叉编译

```bash
# Linux amd64（在任意平台上均可交叉编译）
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o palworld-admin .
# Windows
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -o palworld-admin.exe .
```

> 无 CGO，交叉编译无需特殊工具链；但发布版本仍建议在 Ubuntu 22.04 容器内构建并做一次实际运行验证。
