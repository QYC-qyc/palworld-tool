# PalAdmin 开发约定

新窗口开始工作前先读此文件，了解代码在哪、规则是什么。

## 上下文管理（重要）
- 分析、调研、设计等过程性内容**尽量写到 `docs/` 下的 `.md` 文件**，不要全部堆在模型对话上下文里
- 大块参考资料、长文件分析、第三方项目调研结果，先落盘成 md，模型只读取结论和关键片段，否则上下文膨胀会导致回答变慢、成本升高
- 新功能/重构前先在 `docs/` 写方案文档，实现时按文档推进
- 临时分析文件命名：`docs/参考XXX分析.md`、`docs/XXX方案.md`，完成后保留或删除视价值而定

## 技术栈
Go 1.22 + Gin + bbolt | Vue 3 + TypeScript + Naive UI + Vite + Leaflet
运行环境：Linux（Ubuntu 22.04/Debian 12），systemd

## 代码位置

### 后端
- 路由注册：`api/router.go`（静态文件 `/assets`、`/data`、`/icons`、`/map` 必须注册）
- 数据库 bucket：`internal/database/bbolt.go`
- 设置键常量：`service/settings.go`
- 新增可编辑设置：必须在 `api/settings.go` 的 `isEditableKey()` 注册
- 游戏配置 schema（字段定义/范围/分类）：`internal/palconfig/schema.go`
- ini 解析：同文件 `ParseFile()`/`WriteFile()`，读取时去引号、写入时加引号
- 游戏服进程管理：`internal/gamesrv/manager.go`，支持原生 Linux 和 Wine 两种模式；由设置 `paldefender.wine_mode` 决定（开启用 Wine 启动 Windows 版服务端加载 PalDefender，关闭用原生 Linux 版），切换需重启游戏服
- 面板自更新：`internal/updater/updater.go`
- 外部监控与存档审计：`internal/detect/detect.go`（等级突变/同IP多开/帕鲁异常/复制/物品堆叠，不 hook 进程；封禁/踢出通过 PalDefender 执行，PD 不可用时踢出回退官方 REST）。开关在设置页「反作弊检测」，配置键 `detect.enabled`/`detect.ban_on_detect`/`detect.kick_on_detect`，每次检测实时从设置读取（`detect.ConfigFromSettings`）
- PalDefender 集成：`api/paldefender.go`（Wine/DLL 安装）、`api/paldefender_api.go`（REST API 代理前缀 `/api/paldefender/api`、一键生成 Token `/paldefender/create-token`）、`internal/paldefender/client.go`（客户端）。封禁/踢人/广播/私聊等管理操作统一走 PalDefender，关服/白名单/存档数据等 PD 未覆盖的仍走官方 REST
- 审计日志：`service/audit/audit.go`，操作类 API 调用 `audit.Add()`
- 定时任务：`internal/task/task.go`
- 在线玩家位置：`internal/tool/rest_api.go` 的 ShowPlayers() 返回 LocationX/Y

### 前端
- 页面：`web/src/views/`，API 封装：`web/src/api/`
- 路由：`web/src/router/index.ts`，菜单：`web/src/views/Layout.vue`
- 字段说明统一用问号图标 + NTooltip（HelpCircleOutline），不在标签后直接写文字
- tooltip 深色背景样式：`:deep(.n-tooltip){background:#1f1f1f!important;color:#fff!important}`
- 耗时操作（安装/更新）用进度弹窗 + 后端轮询接口
- 地图：Leaflet Simple CRS，瓦片在 `web/public/map/tiles/`

## 配置字段规则
- 字段 Min/Max/Step 参考 LootLab：https://lootlab.cn/palworld/settings
- 配置分类（8个页签）：服务器、世界、玩家、帕鲁、战斗、经济与掉落、据点、公会
- 字段 Label 参考官方文档和 LootLab 的中文命名
- 难度预设：选 Easy/Normal/Hard 自动填倍率，改任意倍率自动切回 None
- 新增字段后检查解析时是否需要去引号（字符串类型自动处理，Raw/Multi 类型不加引号）
- Multi 类型输出为 `(A,B,C)` 括号列表

## 地图功能
- 两张地图共用同一套游戏全局坐标（REST API 的 location_x/y 不变），Leaflet L.CRS.Simple，zoom 0-6，256px/瓦片，归一化到 256x256 空间：
  - 主世界 Palpagos：瓦片 `web/public/map/tiles/{z}/{x}/{y}.webp`，边界 `LAND_SCAPE = [349400, 724400, -1099400, -724400]`
  - 世界树 Feybreak（1.0 新地图）：瓦片 `web/public/map/tiles-feybreak/`，边界 `FEYBREAK_LAND_SCAPE = [689148.5, -476400, 347351.5, -818197]`，跨度约为主世界 1/4.24，细节更密
- 瓦片下载脚本：`scripts/download-map-tiles.py [--map palpagos|feybreak] [--all]`，从 palworld.gg（主世界 tiles/、新地图 world-tree-tiles/）下载 PNG 并用 Pillow 转 webp
- 坐标换算（`web/src/utils/mapCoords.ts`）：`MAP_CONFIGS` 配置两张图的边界/瓦片URL/POI URL/名称；`toMapPosition(p, map)`、`fromMapPosition(p, map)`、`toMapDistance(d, map)`；`detectMap(x,y)` 按坐标判定所属地图（用于自动模式）；`pointInMap(x,y,map,margin)` 过滤当前图内标记
- 地图切换：默认主世界，控制面板可切「主世界/世界树/自动」；自动模式按在线玩家多数坐标选图；切换时换瓦片层并重绘所有图层
- 地图覆盖物：在线/离线玩家、公会据点（zoom<5 网格聚合、zoom>=5 显示范围圈）、Boss 塔、快速旅行点；玩家/据点按当前地图边界过滤
- 据点数据来源：Level.sav 的 `BaseCampSaveData`，由 sav_cli 解析（`module/structurer.py` 的 `structure_base_camp`），需要 palworld-save-tools>=0.24.0（内置 base_camp RawData decoder）
- 静态点：`web/public/data/map-points.json`（主世界 9 Boss塔+137传送点）、`map-points-feybreak.json`（天坠之地 4+15），标记图标 `web/public/map/icons/`（两图共用）；POI 坐标从 palworld.gg 前端 chunk 提取
- 参考实现：`_palworld-server-tool/web/src/views/PcHome/component/MapView.vue`；分析见 `docs/参考项目地图实现分析.md`、`docs/新地图调研.md`

## 静态资源
- 图标：`web/public/icons/`（tech 464个、pals 299个、items 864个，均压缩到 64/128px）
- 数据 JSON：`web/public/data/`（tech_list.json、pal_list.json、item_list.json、map-points.json、map-points-feybreak.json）
- 地图：`web/public/map/`（tiles/ 主世界瓦片、tiles-feybreak/ 天坠之地瓦片、icons/ 标记图标）
- 后端必须注册所有静态目录路由，否则资源 404

## 更新机制
- 后端下载 tar.gz 到临时目录，setsid+nohup 执行替换脚本，**不能 os.Exit 自杀**
- 下载镜像：ghfast.top / gh-proxy.com / ghproxy.net / 直连
- 前端轮询 `/api/updater/status` 看下载进度，服务重启后轮询 `/health`

## 构建与发布
- 后端编译：`go build -o paladmin .`
- 前端构建：`cd web && npm run build`
- CI 必须用 ubuntu-22.04（glibc 2.35 兼容旧服务器）
- Release 产物：paladmin + web/dist/ + data/ + icons/ + map/ + sav_cli + paladmin.service
- 打 tag vX.Y.Z，只推 Gitee（origin），Gitee 会自动同步到 GitHub，保留最近 5 个 tag
- 发版后自动清理旧 tag：`scripts/cleanup-tags.sh 5`
- 推送（新提交/新 tag）只需 `git push origin main <tag>`，**不要单独 push github**（会和 Gitee 同步冲突导致 ref lock）
- 注意：Gitee→GitHub 自动同步只同步新增/更新，**不同步删除**；因此删 tag 必须 Gitee 和 GitHub 两端都删，`cleanup-tags.sh` 已处理

## 常用命令
```bash
# 编译后端
go build -o paladmin .
# 构建前端
cd web && npm run build
# 本地运行
./paladmin
# 提交推送（只需推 Gitee，会自动同步到 GitHub）
git add -A && git commit -m "msg" && git tag -a v1.x.x -m "v1.x.x"
git push origin main v1.x.x
scripts/cleanup-tags.sh 5
```
