# PalAdmin 开发规范

> 新窗口开始工作前**必读**。本文档记录当前架构、代码位置、开发约定和已踩过的坑。
> 最后更新：2026-08-21

## 一、项目概况

幻兽帕鲁（Palworld）服务器管理与反作弊面板。

- **后端**：Go 1.22 + Gin + bbolt（嵌入式 KV，无外部数据库）
- **前端**：Vue 3 + TypeScript + Vite + Naive UI + Leaflet
- **运行环境**：Linux，**Docker Compose 双容器部署**（面板 + 游戏服）
- **游戏服**：Windows 版 PalServer，通过 GE-Proton 运行，加载 PalDefender 反作弊 DLL
- **当前大版本**：v3.x（Docker 化）。历史有 v1.x（Linux+Proton 二进制）、v2.x（Windows 原生），均已弃用，tag 保留在 git 历史

## 二、架构（重要）

```
浏览器 ──http://IP:8190──► paladmin 容器（Go+Vue）
                              │
                              ├── /var/run/docker.sock ──► docker CLI 管控 gameserver 容器
                              │                                （start/stop/exec/logs）
                              └── http://gameserver:8212 ──► gameserver 容器
                                                                SteamCMD + GE-Proton
                                                                + PalServer.exe
                                                                + PalDefender DLL
```

- **gameserver 容器**：`docker/gameserver/Dockerfile`，内含 SteamCMD + GE-Proton + 启动脚本
- **paladmin 容器**：`docker/paladmin/Dockerfile`，多阶段构建（Node 编前端 → Go 编后端）
- 两容器同 Docker 网络 `palnet`，面板用容器名 `gameserver` 连 REST
- 数据卷：`./data/gameserver`（游戏存档/配置/DLL）、`./data/paladmin`（面板数据库）
- 纯镜像部署用 `docker-compose.prod.yml`（从 GHCR 拉镜像，不依赖源码）

### 容器化判定逻辑
- 环境变量 `GAMESERVER_CONTAINER` 设为容器名时，`internal/gamesrv/manager.go` 走 docker 分支（`m.docker != nil`）
- Start/Stop/Install/Logs/GetStatus 都有 `if m.docker != nil` 分支
- docker 操作封装在 `internal/gamesrv/docker.go`（Linux）和 `docker_windows.go`（Windows stub）
- 非容器模式（宿主机直接装 Proton）仍保留，向后兼容

## 三、代码位置

### 后端
- 入口：`main.go`（加载配置、初始化 DB、注册路由、启动 HTTP）
- 路由：`api/router.go`（`/api/*`，JWT 鉴权在 `internal/auth/`）
  - 静态资源：`/assets`、`/data`、`/icons`、`/map` 必须注册，否则前端 404
- 配置：`internal/config/`，viper 读取 config.yaml，动态设置存 bbolt
- 设置键常量：`service/settings.go`；**新增可编辑设置必须在 `api/settings.go` 的 `isEditableKey()` 注册**
- 游戏服管理：`internal/gamesrv/manager.go`（核心，含 Proton/Docker 两种模式）
- 游戏配置：`internal/palconfig/schema.go`（117 个字段定义/分类/范围）
- ini 解析：同文件 `ParseFile()/WriteFile()`，读取去引号、写入加引号
- PalDefender：
  - `api/paldefender.go`：DLL 安装/卸载、Token、Proton 一键安装
  - `api/paldefender_api.go`：REST API 代理前缀 `/api/paldefender/api`
  - `internal/paldefender/client.go`：PD REST 客户端
  - 封禁/踢人/广播/私聊/玩家管理**统一走 PalDefender**；关服/白名单/存档等 PD 没有的走官方 REST
- GitHub 镜像：`internal/github/mirrors.go`（**唯一**的镜像配置源，所有从 GitHub 下载都走这里）
  - `DownloadMirrors()`：release 文件下载镜像前缀
  - `FetchRelease()`：多镜像获取 release JSON
  - `DownloadToFile()`/`DownloadToFileWithProgress()`：多镜像下载
- 自更新：`internal/updater/`（测速选最快镜像、替换重启）
- 存档解析：`internal/tool/`（参考 palworld-save-tools），sav_cli 用 PyInstaller 打包
- 审计：`service/audit/`，操作类 API 调 `audit.Add()`
- 定时任务：`internal/task/task.go`

### 前端
- 页面：`web/src/views/`，API 封装：`web/src/api/`
- 路由：`web/src/router/index.ts`，菜单：`web/src/views/Layout.vue`
- 通用组件：`web/src/components/`（PageHeader/StatusTag/PlatformBadge/EmptyState）
- composables：`web/src/composables/`（useTheme 暗色模式）
- 字段说明统一用问号图标 + NTooltip（HelpCircleOutline），不在标签后写文字
- tooltip 深色样式：`:deep(.n-tooltip){background:#1f1f1f!important;color:#fff!important}`
- 耗时操作（安装/更新）用进度弹窗 + 轮询后端接口

### 部署
- `docker/gameserver/`：游戏服镜像（Dockerfile + entrypoint.sh）
- `docker/paladmin/`：面板镜像（Dockerfile + entrypoint.sh）
- `docker-compose.yml`：源码构建
- `docker-compose.prod.yml`：纯镜像部署（用户只需要这个文件）
- `scripts/install.sh`：二进制直装脚本
- `.github/workflows/release.yml`：CI（构建 amd64/arm64 二进制 + 两个 GHCR 镜像 + 自动设镜像公开）

## 五、开发约定

### 通用
- 分析/调研/方案先写到 `docs/`，不要全堆在对话上下文
- 大块参考资料、长文件分析先落盘 md，只读取结论和关键片段
- 新功能/重构前先写方案文档

### 后台子代理使用纪律（重要）
用后台子代理做多文件重构后，**必须立即验证**，不能假设它做完：
1. `go build ./...`、`go vet ./...`、`cd web && npm run build` 全通过
2. grep 检查前端模板引用的函数/变量都在 `<script>` 定义（子代理被中断时常漏写函数体）
3. 前端调用的 API 路径与后端 `api/router.go` 注册的路由一一对应
4. 检查旧概念残留（重构后搜旧变量名/旧路由/旧 import）
5. 子代理状态 stopped / "No completion record" 表示被中断，改动可能写了一半，按清单逐项核查

### Go
- 错误处理必须检查 error，不要用 `_` 忽略关键错误
- 新增设置键记得在 `isEditableKey()` 注册
- HTTP 响应统一用 `SuccessResponse{Success,Message}` / `ErrorResponse{Error}`，不要散落 `gin.H{"error":...}`
- 跨平台代码用 `//go:build windows` / `!windows` 分离，参考 `proc_*.go`、`docker_*.go`
- 从 GitHub 下载必须走 `internal/github` 包，**不要硬编码镜像 URL**
- 进程管理不要用 wineserver -k（Proton 不用）

### 前端
- 所有 API 调用走 `web/src/api/` 封装，不要在组件里直接 fetch
- 列表页统一用 n-data-table，加分页和搜索
- 图标用 WebP（`web/public/icons/` 下 1615 个图标已全部转好），新增图标也用 WebP
- 暗色/亮色主题用 useTheme，组件用 Naive UI 的主题变量

### 游戏配置
- 字段 Min/Max/Step 参考 LootLab：https://lootlab.cn/palworld/settings
- 分类（8 个页签）：服务器、世界、玩家、帕鲁、战斗、经济与掉落、据点、公会
- 难度预设：Easy/Normal/Hard 自动填倍率，改任意倍率自动切 None
- 字符串类型自动去引号，Raw/Multi 类型不加引号
- Multi 类型输出 `(A,B,C)`

### Git / 发版
- 只推 Gitee（origin），Gitee 自动同步 GitHub，**不要单独 push github**（会 ref lock）
- Gitee→GitHub 同步只同步新增/更新，**不同步删除**；删 tag 必须两端都删，`scripts/cleanup-tags.sh` 已处理
- 打 tag：`git tag -a vX.Y.Z -m "..." && git push origin main vX.Y.Z`
- 保留最近 5 个 tag（`scripts/cleanup-tags.sh 5`）
- CI 会自动：构建 amd64/arm64 二进制 → 上传 Release → 构建并推送 GHCR 镜像 → 设镜像公开
- GHCR 镜像名：`ghcr.io/qyc-qyc/paladmin`、`ghcr.io/qyc-qyc/palworld-gameserver`
- `GITHUB_REPOSITORY_OWNER` 含大写时用 bash `${VAR,,}` 转小写（GHCR 要求全小写，已踩坑）

## 六、已踩过的坑（不要再犯）

1. **SteamCMD "Missing configuration"**：初始化命令必须带 `@sSteamCmdForcePlatformType windows`，且平台参数要在 `+login` 之前作为启动参数
2. **GE-Proton 下载卡住**：直连 api.github.com 常超时；统一走 `internal/github` 镜像，单请求 20s 超时自动切换
3. **apt-get exit 100**：`steam-libs-i386` 是 Arch 包名，Debian/Ubuntu 不存在；Debian 用 `libc6:i386`、`libstdc++6:i386`、`libgcc-s1:i386`、`lib32gcc-s1`、`lib32stdc++6`，加 `DEBIAN_FRONTEND=noninteractive` 和 `--no-install-recommends`
4. **GE-Proton 架构选错**：不能取第一个 `.tar.gz`，要按 `runtime.GOARCH` 选（amd64 无后缀、arm64 带 `-aarch64`），否则在 ARM 服务器下错包
5. **GHCR 镜像 401**：package 默认私有，CI 需用 `gh api -X PATCH user/packages/container/<pkg> -f visibility=public` 设公开；需要 `packages: write` 权限
6. **Windows 解压 steamcmd.zip 后找不到 exe**：不要依赖 PowerShell Expand-Archive，用 Go 标准库 `archive/zip` 解压，并递归查找 steamcmd.exe（可能在子目录）
7. **web/dist 小文件过多导致 zip 解压慢**：1.2 万个图标/瓦片文件 → 打包成单个 `web.dat`（zip），运行时释放到 exe 同目录（`internal/webdata/`）
8. **sav_cli 架构问题**：PyInstaller 不能交叉编译，Linux runner 编出的是 ELF，打进 Windows zip 会导致存档解析失效；Windows 版 sav_cli 必须在 windows-latest runner 上编
9. **root 降权**：Linux 原生模式 PalServer 拒绝 root 启动，需 `ensureRunUser()` 找目录属主或建 paladmin 用户；**Docker 模式不需要**（容器内用 steam 用户）
10. **Proton 启动环境变量**：必须设 `PROTON_DIST_PATH`、`STEAM_COMPAT_DATA_PATH`、`STEAM_COMPAT_CLIENT_INSTALL_PATH`、`WINEDLLOVERRIDES=d3d9=n,b`
11. **`/var/run/docker.sock` 权限**：paladmin 容器要挂载它才能用 docker CLI 管控 gameserver；面板内的 docker 命令依赖宿主机 docker
12. **GitHub 镜像测速**：下载大文件前用 Range 请求前 512KB-1MB 测速，选最快镜像；测速失败用直连兜底
13. **`os.Getenv` 读不到容器环境变量**：确保 docker-compose.yml 里 environment 段正确传递，GAMESERVER_CONTAINER 是启用 docker 管控模式的关键

## 七、常用命令

```bash
# 后端
go build -o paladmin .
go test ./...
go vet ./...

# 前端
cd web && npm install && npm run build && cd ..
cd web && npm run dev          # 开发模式（前端代理到后端，看 vite.config.ts）

# Docker
docker compose build
docker compose up -d
docker compose logs -f paladmin
docker compose logs -f gameserver
docker compose exec gameserver bash
docker compose exec gameserver /home/steam/entrypoint.sh update

# 纯镜像部署（用户视角）
mkdir -p ~/paladmin && cd ~/paladmin
curl -fsSL -o docker-compose.yml \
  https://gitee.com/qyc-qyc/palworld-tool/raw/main/docker-compose.prod.yml
docker compose up -d

# 发版
git add -A && git commit -m "msg"
git tag -a v1.x.x -m "v1.x.x"
git push origin main v1.x.x
scripts/cleanup-tags.sh 5
```

## 八、待办 / 已知问题

- GHCR 镜像构建在 CI 偶发失败（gameserver 镜像下载 GE-Proton 大文件），可重跑
- ARM64 上 Proton 跑 x86_64 Windows 游戏需 box64，`installProton` 已尝试自动装但兼容性不保证
- 面板的"安装 SteamCMD"按钮在 gameserver 镜像里已预装，通常不需要点
- 前端列表分页目前是前端分页（数据已全量返回），数据量大时可考虑后端分页
