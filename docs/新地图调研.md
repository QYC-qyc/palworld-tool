# Palworld 1.0 新地图（Feybreak / 天坠之地）瓦片与坐标调研

> 调研日期：2026-08-17
> 目标：判断 1.0 新地图能否像主世界一样用 Leaflet 瓦片实现，并给出坐标映射与落地方案。

## 结论速览

- **瓦片可公开获取**：palworld.gg 提供完整的新地图瓦片，路径 `https://palworld.gg/images/world-tree-tiles/{z}/{x}/{y}.png`，z=0~6，256×256 PNG，64×64 网格，结构与主世界瓦片完全一致。
- **坐标同属一个全局坐标系**：新地图与主世界共用 UE 全局坐标（REST API 的 `location_x/location_y` 一致），只是位于不同区域。新地图坐标边界已从 palworld.gg 前端代码中精确提取。
- **推荐方案：切换底图（两个地图实例 / 一套可切换的瓦片层 + 坐标边界）**，不推荐单实例叠加（两图比例尺不同）。可按玩家坐标自动判断所在地图，也可手动切换。

---

## 1. Palworld 1.0 新地图基本情况

- 1.0 更新于 **2025 年 12 月**发布，新增大陆英文名为 **Feybreak**，中文官方译名为 **天坠之地**（LootLab 等中文站使用此名；"绯碎之地"为非官方音译/异写）。
- palworld.gg 在站点内把该地图路由命名为 **World Tree（世界树）**，页面路径 `/map/world-tree`（主世界为 `/map`）。世界树是新地图上的核心地标，palworld.gg 用它作为整张地图的标识。
- 新大陆位于原有 Palpagos（帕尔帕戈斯）群岛的**东南方向**，与主世界在游戏内是**同一张 UE 大世界地图上的不同区域**，通过传送点/传送门往来，并非独立存档。
- 玩家在两张地图间切换：通过新地图上的传送点（Fast Travel）与主世界传送网络连通，部分入口为特殊传送门。切换后玩家仍在同一服务器、同一坐标体系内。

## 2. palworld.gg 瓦片（已确认可用）

### 主世界（现有）
- URL：`https://palworld.gg/images/tiles/{z}/{x}/{y}.png`
- 参考项目 `_palworld-server-tool/map_down.py` 即下载此路径；本项目 `web/public/map/tiles/` 是其 WebP 转码版本。

### 新地图 Feybreak / World Tree（本次新发现）
- **URL：`https://palworld.gg/images/world-tree-tiles/{z}/{x}/{y}.png`**
- 来源：palworld.gg 新地图页面 chunk `/_nuxt/dzPAlgc0.js` 中的 maplibre 样式定义：
  ```js
  sources:{gamemap:{type:"raster",
    tiles:[window.location.origin+"/images/world-tree-tiles/{z}/{x}/{y}.png"],
    tileSize:256,minzoom:0,maxzoom:6}}
  ```
- 实测：
  - z=0~6 均返回 200；z=7 返回 404（与主世界一致）。
  - 每级均为完整 `2^z × 2^z` 网格：z6 为 64×64（共 4096 张），全网格总计 5461 张。
  - 瓦片为 **256×256 PNG（RGBA）**；非空瓦片约 130KB，边缘海洋空白瓦片约 665 字节（仍返回 200，可整网格下载）。
  - **无 webp 版本**（`/0/0/0.webp` 返回 404），需自行转码或直接用 PNG。
- 页面通过独立路由 `/map/world-tree` 承载，即 palworld.gg 自身也是"切换底图"而非同屏叠加。

### 参考项目 `_palworld-server-tool` 现状
- `map_down.py` 仍只下载主世界 `tiles/`，未包含 `world-tree-tiles/`。
- `web/src/views/PcHome/component/MapView.vue` 仅支持单地图（`LAND_SCAPE = [349400,724400,-1099400,-724400]`）。
- git log 显示 2026-07-13 有 `da30254 chore(map): update map tiles`（仅更新主世界瓦片，未加第二地图）；1.0 数据更新（`18df587`）只更新了物品/帕鲁/技能数据，未涉及地图。即参考项目**尚未实现新地图支持**，需要我们自行扩展。

## 3. 其他瓦片来源

### LootLab（https://lootlab.cn/palworld/map）
- 使用 **Leaflet** 渲染，瓦片为 WebP，页面内出现 `/tiles/{z}/{x}/{y}.webp` 引用，标注"适配版本 1.0"，图层列表含"世界树随机帕鲁""天坠之地（6 处）"等新地图 POI。
- 直接请求 `https://lootlab.cn/tiles/{z}/0/0.webp` 返回 404，真实瓦片宿主在其 JS 动态加载的子域/CDN 上（未在首屏 HTML 暴露），定位成本较高。
- LootLab 把新地图 POI 与主地图放在同一视图，但其瓦片基底似乎只渲染当前所选区域，未提供比 palworld.gg 更易获取的公开瓦片路径。
- 结论：**palworld.gg 是更直接、已验证的瓦片来源**，LootLab 仅作为中文命名与 POI 数据的旁证。

## 4. 坐标系统（关键）

palworld.gg 前端对两张地图使用各自的"游戏坐标 → 地图归一化坐标"函数，函数体直接暴露了世界边界常量。

### 主世界 Palpagos（chunk `DFoYuZZt.js`）
```js
function R(e){
  const d = (e[0] - -1099400) / 1448800,   // x: [-1099400, 349400]
        c = (e[1] - -724400)  / 1448800;   // y: [-724400, 724400]
  return [-256 + 256*d, 256*c];
}
```
与本项目 `web/src/utils/mapCoords.ts` 的 `LAND_SCAPE = [349400, 724400, -1099400, -724400]` 完全一致。

### 新地图 Feybreak / World Tree（chunk `dzPAlgc0.js`）
```js
function y(e){
  const d = (e[0] - 347351.5) / 341797,   // x: [347351.5, 689148.5]
        _ = (e[1] - -818197)  / 341797;   // y: [-818197, -476400]
  return [-256 + 256*d, 256*_];
}
```
两图随后都用同一个 `w()` 把归一化坐标转为 maplibre 的经纬度：
```js
function w(e){
  const t =  e[1]/256, a = -e[0]/256;
  const {lng, lat} = new MercatorCoordinate(t, a, 0).toLngLat();
  return [lng, lat];
}
```

### 新地图边界（按本项目 `[maxX, maxY, minX, minY]` 约定）

```ts
// Feybreak / 天坠之地
export const FEYBREAK_LAND_SCAPE = [689148.5, -476400, 347351.5, -818197] as const
//                              maxX       maxY     minX     minY
// 跨度：341797 × 341797（正方形）
```

| 地图 | minX | maxX | minY | maxY | 世界跨度 |
|---|---|---|---|---|---|
| Palpagos 主世界 | -1,099,400 | 349,400 | -724,400 | 724,400 | 1,448,800 |
| Feybreak 天坠之地 | 347,351.5 | 689,148.5 | -818,197 | -476,400 | 341,797 |

### 两图坐标关系

- **同一全局坐标系**：`location_x/location_y` 是同一套 UE 坐标。Feybreak 位于 Palpagos 东南侧——x 范围在主世界东侧（347K 起，主世界 x 上限 349K，几乎接壤），y 范围偏南（-818K~-476K，主世界 y 下限 -724K，部分重叠）。
- 因此玩家在新地图时，REST API 返回的 `location_x/location_y` 仍是全局坐标（约 x≈500000、y≈-600000 量级），**不是独立坐标系**。
- 两图比例尺不同：主世界 1,448,800 单位映射到 16384px（z6），新地图 341,797 单位映射到同样 16384px——新地图瓦片每像素代表的世界距离约为主世界的 **1/4.24**，细节更密。
- 坐标判定（用于自动切图）：
  - 落在 `x∈[347351.5, 689148.5]` 且 `y∈[-818197, -476400]` → 新地图；
  - 其余（主世界范围，或边界外）→ 主世界。
  - 两图在 x≈348K、y≈-724K~-476K 一带有极小邻接/重叠区，边界据点可能误判，建议同时提供**手动切换**开关兜底。
- 注：以上边界来自 palworld.gg 对游戏数据的整理，置信度高；建议在 1.0 服务器上线后用一名实际位于新地图的玩家坐标做一次验证。

## 5. 关于已删除的 `treemap.webp`

- 该文件在 commit `d531662`（"地图使用两层图片叠加"）引入，由原 `world.webp` 改名而来；在 `d0ba344`（地图功能重写）中随瓦片化改造一并删除。
- 从 git 历史导出（`git show d0ba344^:web/public/map/treemap.webp`）确认：**4096×4096 WebP，内容正是天坠之地地形全貌**（西北雪原、西部沙漠、东北火山、中部世界树森林、南端尖角，与 palworld.gg `/map/world-tree` 截图一致）。
- 旧 `PlayerMap.vue` 里以 `L.imageOverlay('/map/treemap.webp', [[0,0],[86,85]], {opacity:0.9})` 叠加在主地图左上角——**仅为一张未做地理配准的缩略图**（占主图约 1/3 区域），并非真正的新地图瓦片层。当时 d531662 commit message 称之为"资源/树分布叠加层"，但实际画面是完整地形图，属于早期占位做法，已被瓦片化重写废弃，**不可直接复用**为新地图方案。
- 其来源应为社区/palworld.gg 公开的新地图渲染图（非瓦片拼接，z4 瓦片 16×16 可拼出 4096×4096，但该文件提交早于本次瓦片调研，具体出处无法从 git 追溯）。

## 6. 推荐实现方案

### 方案：切换底图（推荐）

仿照 palworld.gg 的做法，用**一个 Leaflet 地图 + 可切换的瓦片层与坐标边界**，而非双实例叠加。

1. **下载新地图瓦片**
   - 新增下载脚本（或改造 `map_down.py`）拉取：
     `https://palworld.gg/images/world-tree-tiles/{z}/{x}/{y}.png`
   - z=0~6，每级 0..2^z-1 全网格，共 5461 张；转码为 WebP 存放到：
     `web/public/map/tiles-feybreak/{z}/{x}/{y}.webp`
   - 注意：palworld.gg 只提供 PNG，需用 cwebp/ sharp 等转 WebP 以保持与现有 `tiles/` 一致的体积与格式。

2. **坐标工具扩展**（`web/src/utils/mapCoords.ts`）
   - 新增 `FEYBREAK_LAND_SCAPE = [689148.5, -476400, 347351.5, -818197]`。
   - 把 `toMapPosition / fromMapPosition / toMapDistance` 改为接收当前地图边界参数（或导出两个实例：主世界、新地图），不再写死单一 `LAND_SCAPE`。
   - 新增 `detectMap(x, y): 'palpagos' | 'feybreak'`：按上述坐标范围判定。

3. **PlayerMap.vue 改造**
   - 增加地图状态（`palpagos` / `feybreak`），切换时更换 `L.tileLayer` 的 URL 模板（`/map/tiles/{z}/{x}/{y}.webp` ↔ `/map/tiles-feybreak/{z}/{x}/{y}.webp`）与坐标边界。
   - 据点圆圈半径、传送点/Boss 塔坐标等 POI 数据需按当前地图坐标系分别提供（新地图的传送点/塔坐标可从 palworld.gg `dzPAlgc0.js` 的 `G0/Z0/Y0/...` 数组提取，均为 `[x,y]` 全局坐标）。
   - 玩家/据点打点：根据每个玩家自身坐标判定其所属地图——但单视图一次只显示一张底图，建议：
     - 自动模式：以"当前焦点玩家"或"在线玩家多数"所在地图决定底图；
     - 同时提供手动切换按钮（Palpagos / 天坠之地），切换后只渲染落在当前地图范围内的玩家/据点。

4. **不推荐单实例叠加**
   - 两图世界跨度差 4.24 倍，若在同一 `L.CRS.Simple` 里按真实全局坐标摆放，新地图瓦片需缩放到约 1/4 尺寸才能对齐，Leaflet 标准瓦片层不支持该缩放，会导致两套瓦片分辨率/级别无法匹配。
   - palworld.gg 自身也是 `/map` 与 `/map/world-tree` 两个独立地图视图，印证了切换底图的合理性。

### 落地工作量估算
- 瓦片下载与转码：一条脚本，一次性。
- 前端：`mapCoords.ts` 参数化 + `PlayerMap.vue` 增加切换控件与底图切换逻辑；新地图 POI（传送点/塔）数据整理。
- 参考项目 `_palworld-server-tool` 暂未提供新地图实现，无现成代码可抄，坐标转换逻辑可直接复用本调研提取的常量。
