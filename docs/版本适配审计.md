# 版本适配审计

> 审计日期：2026-08-19
> 背景：面板通过 `paldefender.wine_mode`（"true"=Windows/Wine 模式，否则原生 Linux 模式）切换游戏服版本。

## 已修复的问题（本次）

| 位置 | 问题 | 修复 |
|------|------|------|
| internal/task/task.go:isGameRunning() | 硬编码 pgrep PalServer-Linux-Shipping，Wine 模式下自动备份静默失效 | 按 wine_mode 选进程名（Wine 用 PalServer-Win64-Shipping-Cmd.exe） |
| internal/gamesrv/manager.go:findRunningProcesses() | 同上，Wine 模式状态显示 stopped、可能重复启动 | 新增 palProcessPattern() 按模式分支 |
| internal/gamesrv/manager.go:killAllPalServer() | 停服兜底只杀 Linux 进程，Wine 进程残留 | 按模式 pkill；Wine 模式额外调 wineserver -k |
| api/gameserver.go:saveGameServerConfig() | 只写 bbolt 不同步 viper，导致改安装目录后存档路径推导（EffectiveSavePath）不更新 | 保存时同步 viper.Set |
| api/gamesettings.go:iniPath() 兜底 | 未配置安装目录时固定返回 LinuxServer 路径 | 兜底也按 wine_mode 选 WindowsServer |

## 已正确适配（无需改动）

- api/gamesettings.go:iniPath() 主逻辑、syncConnectionSettings()
- gamesrv manager.go：GetStatus、Start、Install(platform)、shouldUseWine、winServerExePath
- api/paldefender.go:detectAt()（PD 仅 Windows 版）
- 存档目录 Pal/Saved/SaveGames 两版本共用，备份/回档无需区分
- 前端 GameServer / GameSettings / Dashboard 均使用后端返回的 wine_mode 等字段

## 不涉及

- GameUserSettings.ini/Engine.ini（面板不管理）
- internal/tool/rest_api.go（REST 连接由 syncConnectionSettings 从正确版本 ini 同步，连接本身与版本无关）
- internal/detect（走 REST + 存档，不依赖进程名）
- deploy/、Dockerfile、scripts/install.sh、internal/updater（面板自身，与游戏服版本无关）
