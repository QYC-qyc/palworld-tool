# palworld-panel 开发指南

> 新窗口开始工作前**必读**。本文档记录当前架构、代码位置、开发约定和已踩过的坑。
> 最后更新：2026-08-22

## 一、项目概况

幻兽帕鲁（Palworld）服务器管理与反作弊面板。

- **后端**：Go 1.25 + Gin + SQLite（纯 Go 驱动 `modernc.org/sqlite`，无需 CGO，单文件，用户零依赖）
- **前端**：Vue 3 + TypeScript + Vite + Naive UI + Leaflet
- **运行环境**：Linux，两种部署方式都支持：
  - **Docker Compose 双容器**（推荐）：面板 + 游戏服
  - **二进制 + systemd**（`deploy/bare-metal/`）：不想用 Docker 的用户
- **游戏服**：Windows 版 PalServer，通过 GE-Proton 运行，加载 PalDefender 反作弊 DLL
  （PalDefender 不支持原生 Linux 版，所以必须用 Windows exe + Proton）
- **当前大版本**：v3.x（Docker 化）。历史有 v1.x（二进制+systemd）、v2.x（Windows 原生），tag 保留在 git 历史

## 二、架构（重要）

### 部署无关的 Host 抽象

核心设计：`internal/gamesrv/host.go` 定义 `Host` 接口，把"底层运行环境"抽象出来，
业务层（Manager/api/service）只依赖接口，不关心是 Docker 还是裸机。

```
Host 接口（host.go）
├── dockerHost（host_docker.go）    — 通过 docker exec/inspect 管控 gameserver 容器
└── bareMetalHost（host_baremetal.go）— 直接在宿主机跑 Proton 进程（二进制部署）

Manager（manager.go）→ 只持有 m.host，调 m.host.Start()/Stop()/ReadFile() 等
```

Host 接口方法分三类：
- **生命周期**：`Start/Stop/Restart/IsRunning/IsContainerUp/Kind`
- **文件系统**：`ReadFile/WriteFile/Stat/MkdirAll/Remove/RemoveAll/ListDir/GameRoot`
- **存档 & SteamCMD**：`FetchSaved/PushSaved/InstallSteamCMD/InstallOrUpdateGame/Logs`

`NewManager()` 根据环境选实现：设了 `GAMESERVER_CONTAINER` 且 docker 可用 → dockerHost，否则 bareMetalHost。

### Docker 双容器拓扑

```
浏览器 ──http://IP:8190──► palworld-panel 容器（Go+Vue）
                              │
                              ├── /var/run/docker.sock ──► docker CLI 管控 gameserver 容器
                              ├── http://palworld-gameserver:8212 ──► 官方 REST API
                              └── 共享挂载卷（关键）：
                                  ./data/gameserver → /home/steam/palserver
                                  ./data/steamcmd   → /opt/steamcmd
                                  ./data/prefix     → /home/steam/prefix
```

**关键：两容器共享游戏目录/SteamCMD/prefix 三个卷（同容器内路径）**。因此面板对游戏文件的
读写直接走本地文件系统（`os.*`），不再依赖 docker exec/cp。分层清晰：
- **文件操作** → 走挂载卷（`os.ReadFile/WriteFile`），容器停止时也能读写
- **进程操作** → 走 docker（`docker exec entrypoint.sh start/stop`）

`GAMESERVER_GAME_DIR=/home/steam/palserver` 环境变量告诉面板游戏目录已挂载，直接文件访问。

### 容器常驻 + 面板控制游戏进程（方案 A）

gameserver 容器**长期运行**（`entrypoint.sh run` 启动守护循环），游戏进程由面板通过
`docker exec entrypoint.sh start/stop/restart` 控制。好处：容器很少重启，游戏崩溃由守护
循环自动拉起，更新游戏不重启容器。

- 容器 CMD = `run`：`supervise()` 守护循环，游戏崩溃退避重启（10s→30s→60s）
- `start`：清停止标记，守护循环拉起游戏
- `stop`：置停止标记 + `wineserver -k`，守护不再拉起
- `status`：查 pid 文件 / pgrep

### 服务名 vs 容器名（易混淆）

| 用途 | 名称 |
|---|---|
| compose 服务名（`docker compose logs X`） | `palworld-gameserver`、`palworld-panel` |
| 容器名（`docker exec X`、容器间 DNS） | `palworld-gameserver`、`palworld-panel` |
| 阿里云 ACR 镜像名 | `palworld-gameserver`、`palworld-panel` |

现在服务名 = 容器名 = 镜像名，全部统一为 `palworld-gameserver` / `palworld-panel`。

## 三、代码位置

### 后端
- 入口：`main.go`（加载配置、初始化 DB、`ensureComposeFile`、注册路由、启动 HTTP）
- 路由：`api/router.go`（`/api/*`，JWT 鉴权在 `internal/auth/`）
  - 静态资源：`/assets`、`/data`、`/icons`、`/map` 必须注册，否则前端 404
- 数据库：`internal/database/store.go`（SQLite，`Store` 类型封装所有表操作）
- 配置：`internal/config/`，viper 读 config.yaml，动态设置存 SQLite
- 设置键常量：`service/settings.go`；**新增可编辑设置必须在 `api/settings.go` 的 `isEditableKey()` 注册**
- 游戏服管理：`internal/gamesrv/`
  - `manager.go`：核心，持有 `Host`
  - `host.go`：Host 接口定义
  - `host_docker.go` / `docker.go`：Docker 实现
  - `host_baremetal.go`：裸机实现（Proton 进程管理）
  - `gamefs.go`：游戏文件访问层（委托给 Host）
- 游戏配置：`internal/palconfig/schema.go`（字段定义/分类/范围）
- PalDefender：
  - `api/paldefender.go`：DLL 安装/卸载、Token
  - `api/paldefender_api.go`：REST API 代理前缀 `/api/paldefender/api`
  - `internal/paldefender/client.go`：PD REST 客户端
- GitHub 镜像：`internal/github/mirrors.go`（**唯一**镜像配置源，所有 GitHub 下载走这里）
- 自更新：`api/selfupdate.go`（容器模式：内置 compose 模板 + `docker compose pull palworld-panel`）
- 内置 compose：`internal/compose/`（go:embed 打包 docker-compose.prod.yml，自更新时覆盖本地）
- 存档解析：`internal/tool/`，sav_cli 用 PyInstaller 打包
- 审计：`service/audit/`；定时任务：`internal/task/task.go`

### 前端
- 页面：`web/src/views/`，API 封装：`web/src/api/`
- 路由：`web/src/router/index.ts`，菜单：`web/src/views/Layout.vue`
- 通用组件：`web/src/components/`
- 字段说明统一用问号图标 + NTooltip（HelpCircleOutline）；**注意 tooltip 放输入框 suffix
  或 label 里可能弹层不 teleport 导致文字常驻，优先用 GameSettings.vue 里的标准写法**
- 耗时操作（安装/更新）用进度弹窗 + 轮询后端接口

### 部署
- `docker/gameserver/`：游戏服镜像（Dockerfile + entrypoint.sh）
- `docker/palworld-panel/`：面板镜像（Dockerfile + entrypoint.sh）
- `docker-compose.yml`：源码构建；`docker-compose.prod.yml`：纯镜像部署（用户用这个）
- `deploy/bare-metal/`：二进制部署（Dockerfile.binary、systemd service、build 脚本、config 示例）
- `.github/workflows/release.yml`：CI（构建二进制 + GHCR/ACR 双推镜像）

## 五、开发约定

### 通用
- 分析/调研/方案先写到 `docs/`，不要全堆在对话上下文
- 大块参考资料、长文件分析先落盘 md，只读取结论和关键片段
- **重构/调 bug 先用 superpowers skill**：`brainstorming`（改造前）、`systematic-debugging`（查 bug 前，先找根因不要试错）

### 后台子代理使用纪律
用后台子代理做多文件重构后，**必须立即验证**：
1. `go build ./...`（含 `GOOS=linux` 和 `GOOS=windows` 双平台）、`cd web && npm run build` 全通过
2. grep 检查前端模板引用的函数/变量都在 `<script>` 定义
3. 前端调用的 API 路径与后端 `api/router.go` 一一对应
4. 检查旧概念残留（搜旧变量名/旧路由/旧 import）

### Go
- 错误处理必须检查 error，不要用 `_` 忽略关键错误
- 新增设置键记得在 `isEditableKey()` 注册
- HTTP 响应统一用 `SuccessResponse` / `ErrorResponse`
- 跨平台代码用 `//go:build windows` / `!windows` 分离
- 从 GitHub 下载必须走 `internal/github` 包，不要硬编码镜像 URL
- 游戏文件操作走 `gamesrv.Manager` / `Host`，不要直接 `os.*` 操作游戏目录（除非通过 Host）
- **改依赖后必须 `go mod tidy`**，且确认 Docker/CI 的 Go 版本 ≥ go.mod 声明版本

### 前端
- 所有 API 调用走 `web/src/api/` 封装，不要在组件里直接 fetch
- 列表页用 n-data-table，加分页和搜索
- Vue 模板里 ref 会自动解包，传 ref 给函数要注意（曾因此报 "Cannot create property 'value' on string"）

### 游戏配置
- REST API 通过 `PalWorldSettings.ini` 的 `RESTAPIEnabled=True` 启用，**不是命令行参数**
- ini 格式：`OptionSettings=(Key=Value,Key=Value,...)` 单行
- 难度预设：Easy/Normal/Hard 自动填倍率

### Git / 发版
- 只推 Gitee（origin），Gitee 自动同步 GitHub
- Gitee→GitHub 同步不同步删除；删 tag 两端都删
- 打 tag：`git tag vX.Y.Z && git push origin vX.Y.Z && git push github vX.Y.Z`
- 保留最近 5 个 tag（`scripts/cleanup-tags.sh 5`）
- ACR 镜像仓库：`crpi-pwq7gsi7qm6vv08p.cn-chengdu.cr.aliyuncs.com/qyc_pal/`（公开，无需登录拉取）

## 六、已踩过的坑（不要再犯）

1. **游戏退出码 3（僵尸进程 + esync 冲突）**：守护循环反复重启游戏 → 大量 defunct wineserver
   堆积 → 新进程 esync 冲突 → 退出码 3。修复：① 用 tini 作 PID 1（`-g` 转发信号到进程组）回收僵尸；
   ② 禁用 esync/fsync（`PROTON_NO_ESYNC=1` 等，单机服务器不需要）；③ 启动前后 `wineserver -k`
2. **Proton "No compat data path" / "is not owned by you"**：降权 `su steam -c` 时必须显式传
   `STEAM_COMPAT_DATA_PATH`、`STEAM_COMPAT_CLIENT_INSTALL_PATH`（su 不继承 Docker ENV）；
   prefix 目录属主必须是 steam（不能以 root exec 进容器跑 proton 污染 prefix）
3. **REST 参数导致退出码 3**：`-RESTPort/-RESTPassword` 不是 PalServer 命令行参数，传了会崩；
   REST 只能通过 ini 配置
4. **go mod download CI 失败**：换 SQLite 引入的新依赖需要 Go 1.23+，但 Docker/CI 还是 Go 1.22；
   改依赖后要同步升级 `golang:X` 镜像和 `setup-go` 版本，且 `go mod tidy` 补全 go.sum
5. **compose 文件服务名不匹配**：用户本地 compose 是旧版导致 `no such service`；面板镜像内置
   compose 模板（`internal/compose`），自更新时自动覆盖本地
6. **naive-ui tooltip 文字常驻**：tooltip 放 n-input suffix / n-form-item label 里弹层可能不
   teleport，文字直接渲染出来；用 GameSettings.vue 的标准写法
7. **SteamCMD "Missing configuration"**：初始化命令必须带 `@sSteamCmdForcePlatformType windows`
8. **GE-Proton 下载卡住**：直连 github 常超时，走 `internal/github` 镜像
9. **apt-get exit 100**：Debian 用 `libc6:i386` 等，不是 Arch 的 `steam-libs-i386`
10. **GE-Proton 架构选错**：按 `runtime.GOARCH` 选包（amd64 无后缀、arm64 带 `-aarch64`）
11. **machine-id 缺失**：slim 镜像无 `/etc/machine-id`，Proton 启动需要，用 `/proc/sys/kernel/random/uuid` 生成

## 七、常用命令

```bash
# 后端（双平台验证）
CGO_ENABLED=0 GOOS=linux go build -trimpath -o /tmp/pal .
GOOS=windows go build -trimpath -o /tmp/pal.exe .
go mod tidy

# 前端
cd web && npm install && npm run build && cd ..

# Docker（注意用服务名）
docker compose build
docker compose up -d
docker compose logs -f palworld-gameserver
docker compose exec palworld-gameserver bash
docker compose exec palworld-gameserver /home/steam/entrypoint.sh update

# 纯镜像部署（用户视角）
mkdir -p ~/palworld-panel && cd ~/palworld-panel
curl -fsSL -o docker-compose.yml \
  https://gitee.com/qyc-qyc/palworld-tool/raw/main/docker-compose.prod.yml
docker compose up -d

# 发版
git add -A && git commit -m "msg"
git tag vX.Y.Z && git push origin main vX.Y.Z && git push github vX.Y.Z
```
